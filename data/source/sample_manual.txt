# 企业IT运维知识库 - 常见问题与操作指南

## 一、服务器CPU负载过高处理

### 现象
服务器响应变慢，top命令显示CPU使用率持续超过80%，系统日志出现大量超时告警。

### 排查步骤
1. 使用 `top -c` 查看实时进程CPU占用，记录高占用进程PID。
2. 使用 `strace -p PID` 追踪系统调用，判断是否为异常进程。
3. 检查是否有定时任务（crontab）在此时段集中执行。
4. 查看 `/var/log/messages` 和 `/var/log/syslog` 是否有内核或硬件报错。
5. 如果为应用服务（如Java），使用 `jstack` 导出线程栈分析死锁或循环。

### 常见原因
- 业务突发流量，预期内增长 -> 需扩容或限流。
- 恶意进程或挖矿病毒 -> 立即隔离并查杀。
- 内存不足导致频繁swap -> 增加内存或优化应用。
- 日志级别设置为DEBUG，产生大量日志写入 -> 调整为INFO或ERROR。

### 解决方案
- 短期：重启高占用服务或kill异常进程。
- 长期：优化代码、增加服务器资源、配置自动伸缩策略。

## 二、网络连接超时问题

### 现象
用户反馈无法访问业务系统，ping外网正常，但访问特定端口（如80/443）超时。

### 排查流程
1. 检查本地防火墙（iptables/firewalld）是否拦截端口。
2. 使用 `telnet IP PORT` 检测端口连通性。
3. 查看交换机/路由器ACL规则是否限制了访问源IP。
4. 检查服务器上的服务进程是否正常运行（如Nginx、Tomcat）。
5. 查看系统连接数：`netstat -an | grep ESTABLISHED | wc -l`，是否达到系统上限。

### 注意事项
- 若是云服务器，需检查安全组策略。
- 若为HTTPS，检查证书是否过期。
- 多机房场景需排查DNS解析是否正确。

## 三、数据库连接池配置建议

### 背景
应用出现“Connection pool exhausted”报错，新请求无法获取数据库连接。

### 推荐配置参数（以HikariCP为例）
- maximumPoolSize: 根据业务并发量设置，建议 20~50。
- minimumIdle: 建议设为最大池大小的一半，减少创建开销。
- connectionTimeout: 30000ms，超过30秒超时。
- idleTimeout: 600000ms，10分钟空闲释放。
- maxLifetime: 1800000ms，30分钟连接生命周期。

### 监控与调优
- 开启HikariCP metrics（如Micrometer）监控活跃连接数。
- 定期检查慢SQL，优化查询减少连接占用时间。
- 配置连接泄漏检测：`leakDetectionThreshold=60000` 单位ms。

## 四、备份与恢复策略

### 备份类型
- 全量备份：每周日凌晨2点执行，保留最近4周。
- 增量备份：每日凌晨1点执行，保留最近7天。
- 归档备份：每月1日将上月备份打包上传至对象存储。

### 恢复演练
- 每季度进行一次数据恢复演练，验证备份有效性。
- 恢复步骤：
  1. 停止应用服务，防止数据写入。
  2. 从备份介质（如NFS、OSS）拉取备份文件。
  3. 按数据库类型执行恢复命令（如mysql -u root -p < backup.sql）。
  4. 启动服务并进行业务验证。

### 关键指标
- RPO（恢复点目标）：≤ 24小时（可接受丢失一天数据）。
- RTO（恢复时间目标）：≤ 4小时（从故障到业务恢复）。

## 五、常见告警处理方法

### 磁盘使用率超过85%
- 查找大文件：`find / -type f -size +1G -exec ls -lh {} \;`。
- 清理日志目录（/var/log）及临时文件（/tmp）。
- 扩容文件系统（LVM或云盘在线扩容）。

### 内存使用率超过90%
- 检查是否有内存泄漏（使用valgrind或JVM分析工具）。
- 增加swap空间（临时缓解）。
- 考虑升级内存或优化应用内存占用。

### SSL证书即将过期
- 提前30天通过证书管理系统提醒。
- 申请新证书并部署（注意中间证书链完整性）。
- 重启Web服务器生效（nginx -s reload）。
